사람들이 그 방을 어떤 순서로 오가는지, 문이 언제 열리는지를 보여 줍니다.

UML은 세 사람의 방법론을 합친 것입니다럼바우(OMT), 부치, 야콥슨(OOSE)이 각자 쓰던 표기법을 1997년 OMG가 UML 1.1로 표준화했습니다. 2005년 UML 2.0에서 다이어그램이 14종으로 정리됐고, 현재 판은 2.5.1(2017)입니다.
정보처리기사 출제 범위 표시 기출이 가이드는 실무 이해를 위한 자료입니다. 출제 항목에는 기출 표시를 붙였고, 모아 보려면 자격증 대비 탭을 여세요.

구성 요소 기출

UML은 사물(단어), 관계(연결), 다이어그램(문장)으로 이루어집니다. 관계 기호 6개를 구분하는 것이 UML 읽기의 절반입니다.

이 탭 안에서 관계 6사물 4다중성·가시성

관계 6가지 선과 끝 모양으로 구분합니다

연관 기출

Association
실선

두 클래스가 서로 알고 지내는 관계입니다. 방향이 있으면 끝에 화살표를 붙입니다.

예
학생은 여러 강의를 듣는다

집합 기출

Aggregation
빈 마름모

전체와 부분 관계지만 부분이 따로 살 수 있습니다. 마름모는 전체 쪽에 붙입니다.

예
팀이 없어져도 선수는 남는다

합성 기출

Composition
찬 마름모

전체와 부분이 생명을 같이합니다. 전체가 사라지면 부분도 사라집니다.

예
집을 허물면 방도 없어진다

일반화 기출

Generalization
빈 삼각형

"~는 ~의 한 종류다"(is-a) 관계, 곧 상속입니다. 삼각형은 부모 쪽을 가리킵니다.

예
고양이는 동물이다

의존 기출

Dependency
점선 화살표

잠깐 빌려 쓰는 관계입니다. 상대가 바뀌면 나도 영향을 받습니다. 매개변수나 지역 변수로 쓸 때입니다.

예
주문 처리 중에 결제 기능을 호출

실체화 기출

Realization
점선 삼각형

인터페이스가 약속한 기능을 클래스가 실제로 구현하는 관계입니다(can-do).

예
카드결제가 결제 인터페이스를 구현

사물 4가지 다이어그램에 올라가는 단어

구조 사물 기출

Structural Things

시스템의 개념적·물리적 요소입니다.

예
클래스, 인터페이스, 유스케이스, 컴포넌트, 노드

행동 사물 기출

Behavioral Things

시간과 공간에 따라 일어나는 동작입니다.

예
상호작용(메시지), 상태 머신

그룹 사물 기출

Grouping Things

요소를 묶는 상자입니다.

예
패키지

주해 사물 기출

Annotational Things

설명을 덧붙이는 메모입니다. 귀퉁이가 접힌 상자로 그립니다.

예
노트(Note)

다중성과 가시성 선 끝과 이름 앞의 작은 기호

다중성 기출
  • 1 정확히 하나
  • 0..1 없거나 하나
  • * 또는 0..* 0개 이상
  • 1..* 1개 이상
가시성 기출
  • + public: 어디서나
  • - private: 자기 클래스만
  • # protected: 자기 + 자식
  • ~ package: 같은 패키지
스테레오타입

«interface», «include»처럼 겹화살괄호로 요소의 성격을 덧붙입니다.

정적 · 무엇이 있는가

구조 다이어그램 7 기출

시스템을 이루는 요소와 그 연결을 그립니다. 실무에서는 클래스, 컴포넌트, 배포, 패키지를 주로 씁니다.

클래스 다이어그램 기출

Class
가장 많이 씀

클래스의 이름, 속성, 연산과 클래스 사이의 관계를 그립니다. 코드 구조와 가장 가깝습니다.

언제
도메인 모델, DB·코드 설계

객체 다이어그램 기출

Object

특정 순간의 실제 인스턴스와 값을 그립니다. 이름에 밑줄을 긋습니다(주문1: 주문).

언제
클래스 설계를 예시 데이터로 검증할 때

컴포넌트 다이어그램 기출

Component

독립 배포되는 부품과 그 인터페이스를 그립니다. 제공 인터페이스는 원(○), 요구 인터페이스는 반원(◡)입니다.

언제
모듈·서비스 경계 설계, CBD

배포 다이어그램 기출

Deployment

소프트웨어가 어떤 서버·장비(노드)에 올라가 어떻게 통신하는지 그립니다. 노드는 입체 상자로 그립니다.

언제
인프라 구성, 운영 환경 문서

패키지 다이어그램 기출

Package

관련 요소를 폴더 모양 상자로 묶고 패키지 사이 의존을 그립니다.

언제
큰 시스템의 계층·모듈 구조 정리

복합 구조 다이어그램 기출

Composite Structure

클래스 하나의 내부를 열어 부품(part)과 연결(port, connector)을 그립니다.

언제
복잡한 컴포넌트의 내부 협력 설명

프로파일 다이어그램

Profile

특정 분야에 맞게 UML을 확장하는 스테레오타입과 규칙을 정의합니다.

언제
회사·도메인 전용 모델링 규칙을 만들 때
동적 · 어떻게 움직이는가

행위 다이어그램 7 기출

시간에 따른 흐름과 상호작용을 그립니다. 유스케이스, 활동, 시퀀스, 상태 머신 네 가지를 가장 많이 씁니다.

유스케이스 다이어그램 기출

Use Case

사용자(액터)가 시스템으로 무엇을 하는지 기능 단위로 그립니다. 요구사항 도출 단계에서 많이 씁니다.

관계
«include» 반드시 포함, «extend» 조건부 확장

활동 다이어그램 기출

Activity

처리 흐름을 순서도처럼 그립니다. 조건 분기, 병렬 처리, 담당자별 구획(스윔레인)을 표현합니다.

언제
업무 절차, 알고리즘 흐름

상태 머신 다이어그램 기출

State Machine

객체 하나가 이벤트에 따라 상태를 바꿔 가는 모습을 그립니다.

언제
주문·결제처럼 상태가 중요한 객체

시퀀스 다이어그램 기출

Sequence

객체들이 시간 순서대로 주고받는 메시지를 위에서 아래로 그립니다. 실선은 호출, 점선은 응답입니다.

요소
생명선, 활성 상자, 메시지, 조건 블록(alt, loop)

통신 다이어그램 기출

Communication

시퀀스와 같은 메시지를 객체 사이 연결을 중심으로 그립니다. 순서는 메시지 앞 번호(1, 1.1, 2)로 표시합니다. 예전 이름은 협력 다이어그램입니다.

언제
누가 누구와 연결돼 있는지가 중요할 때

상호작용 개요 다이어그램 기출

Interaction Overview

활동 다이어그램 형식으로 여러 상호작용(시퀀스 조각)의 흐름을 엮어 큰 그림을 보여 줍니다.

언제
시퀀스 여러 장을 한 장으로 연결할 때

타이밍 다이어그램 기출

Timing

가로축 시간에 따라 객체 상태가 언제 바뀌는지 그립니다. 시간 제약이 있는 시스템에 씁니다.

언제
임베디드, 통신 프로토콜, 실시간 시스템
